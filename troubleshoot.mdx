title: "Troubleshoot Qualcomm Linux Docker, Sync, and Build Errors"
description: "Solutions for common errors in Docker setup, source sync, compilation, and device flashing during the Qualcomm Linux build workflow."
---

This page provides solutions for the most common issues you may encounter during Docker setup, source sync, compilation, and device flashing. Each section corresponds to a phase in the build workflow, so you can quickly find the error relevant to where your process failed.

## Docker

<AccordionGroup>
  <Accordion title="Cannot connect to the Docker daemon">
    **Full error:**

    ```text
    docker: Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
    ```

    **Solution:** Start the Docker service:

    ```bash
    sudo systemctl start docker
    ```
  </Accordion>

  <Accordion title="HTTP response to HTTPS client">
    **Full error:**

    ```text
    Error response from daemon: Get "https://registry-1.docker.io/v2/": http: server gave HTTP response to HTTPS client
    ```

    **Solution:** Add a Docker registry mirror and restart the service.

    <Steps>
      <Step title="Add a registry mirror">
        Edit `/etc/docker/daemon.json` and add a registry mirror entry:

        ```bash
        sudo vim /etc/docker/daemon.json
        ```

        ```text
        {
           "registry-mirrors": ["https://docker-registry.qualcomm.com"]
        }
        ```

        <Note>
          Do not include `#` comments in the JSON file. Using tabs instead of spaces, or other invisible whitespace characters, can break JSON parsing and cause `docker.service` to fail on startup.

          As an alternative mirror, you can use `"registry-mirrors": ["https://ccr.ccs.tencentyun.com"]`.
        </Note>
      </Step>
      <Step title="Restart the Docker service">
        ```bash
        sudo systemctl restart docker
        ```
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Failed to download from download.docker.com">
    **Full error:**

    ```text
    Failed to download from https://download.docker.com
    ```

    If you cannot access `https://download.docker.com`, install Docker using the Aliyun mirror instead:

    ```bash
    sudo apt update
    sudo apt install apt-transport-https ca-certificates curl gnupg lsb-release
    curl -fsSL http://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo apt-key add –
    sudo add-apt-repository "deb [arch=amd64] http://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable"
    ```
  </Accordion>

  <Accordion title="Docker failure due to virtualization not enabled">
    **Full error:**

    ```text
    Docker failure due to Virtualization not enabled
    ```

    **Solution:** Enable virtualization in your system BIOS. The exact steps vary by system provider. As a general example:

    <Steps>
      <Step title="Enter the BIOS">
        When the system is booting, press the key required to open the BIOS menu.
      </Step>
      <Step title="Navigate to CPU Configuration">
        Switch to the **Advanced** tab and locate the **CPU Configuration** section.
      </Step>
      <Step title="Enable Virtualization Technology">
        Set **Virtualization Technology** to **Enabled**.
      </Step>
      <Step title="Save and restart">
        Save and exit the BIOS, then restart the system.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Permission denied connecting to the Docker daemon socket">
    **Full error:**

    ```text
    Permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock
    ```

    This happens when `qsc-cli` is already installed but your user is not in the Docker group.

    <Steps>
      <Step title="Add your user to the Docker group">
        ```bash
        sudo groupadd docker
        sudo usermod -aG docker $USER
        newgrp docker
        ```
      </Step>
      <Step title="Confirm group membership">
        ```bash
        sudo grep /etc/group -e "docker"
        # This lists users in the Docker group — your user ID must appear here
        ```
      </Step>
      <Step title="Sign out and sign back in">
        Sign out and sign in again for the change to take effect. You can verify group membership with:

        ```bash
        id -a
        # The output string must include 'docker'
        ```
      </Step>
    </Steps>
  </Accordion>
</AccordionGroup>

## Sync

<AccordionGroup>
  <Accordion title="ManifestInvalidRevisionError during repo init or sync">
    **Full error:**

    ```text
    File "/local/mnt/workspace/<userid>/test_repo/.repo/repo/main.py", line 126
       except ManifestInvalidRevisionError, e:
             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    SyntaxError: multiple exception types must be parenthesized
    ```

    This error may appear after installing Repo if:

    - Your `/etc/gitconfig` or `~/.gitconfig` redirects to an internal mirror.
    - Your internal mirror uses a branch prefix, for example:

      ```text
      [url "ssh://<internal mirror>:<port>/tools/repo"]
      insteadOf = https://android.googlesource.com/tools/repo
      insteadOf = https://gerrit.googlesource.com/git-repo
      ```

    **Solution:**

    <Steps>
      <Step title="Remove the existing .repo folder">
        ```bash
        rm -rf .repo
        ```
      </Step>
      <Step title="Set REPO_REV to the mirrored stable branch">
        `REPO_REV` must point to the mirrored branch from the upstream `stable` branch of `https://gerrit.googlesource.com/git-repo`:

        ```bash
        export REPO_REV='aosp/stable'
        ```
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Server certificate verification failed during repo install">
    **Full error:**

    ```text
    Server certificate verification failed. CAfile: none CRLfile: none
    ```

    **Solution:** You can disable SSL certificate verification with git configuration. Consult your IT administrator before doing this.

    ```bash
    export GIT_SSL_NO_VERIFY=1
    git config --global http.sslverify false
    ```

    If your region blocks access to `android.googlesource`, configure git to use the CodeLinaro mirror instead:

    ```bash
    git config --global url.https://git.codelinaro.org/clo/la/tools/repo.insteadOf https://android.googlesource.com/tools/repo
    ```
  </Accordion>

  <Accordion title="git config error: Device or resource busy">
    **Full error:**

    ```text
    error.GitError: git config ('–replace-all', 'color.ui', 'auto'): error: could not write config file /home/$USER/.gitconfig: Device or resource busy
    ```

    This error occurs when your gitconfig does not have the UI color configuration set. This configuration is set by default in Git 1.8.4 and later. Run the following command to enable color output:

    ```bash
    git config --global color.ui auto
    ```
  </Accordion>

  <Accordion title="Error saving credentials: disk quota exceeded">
    **Full error:**

    ```text
    [Error]: Failed preparing build for compilation. Error: Error setting docker credentials. Error: "Error saving credentials: error closing temp file: close /usr2/<userid>/.docker/config.json3322274803: disk quota exceeded"
    ```

    QSC CLI uses only a few kilobytes of home directory space. Clear a few MB from your home directory and retry.
  </Accordion>

  <Accordion title='The "path" argument must be of type string. Received undefined'>
    **Full error excerpt:**

    ```text
    qsc-cli chip-software download --workspace-path '/local/mnt/workspace/<userid>/K2L/QSC_CLI_BUILD/build' --product 'QCM6490.LE.2.0' --release 'r00004.2' --distribution 'Qualcomm_Linux.SPF.2.0|TEST|DEVICE|PUBLIC'
    [Info]: Starting qsc-cli version 0.0.0.7
    (node:2924765) ExperimentalWarning: The Fetch API is an experimental feature. This feature could change at any time
    (Use `qsc-cli --trace-warnings ...` to show where the warning was created)
    [Info]: Checking if Workspace already exists
    [Info]: Saved updated Workspace info
    [Info]: Workspace Setup Completed
    [Error]: The "path" argument must be of type string. Received undefined
    ```

    **Solution:** This error occurs when QSC CLI is incompatible with Qlauncher. Qlauncher is deprecated and will be replaced by a new application from QSC. If Qlauncher is in your workspace, run:

    ```bash
    # Back up the workspace metadata file if you want to preserve workspaces created with Qlauncher.
    # These files only work with the Qlauncher app, which you can reinstall later.
    # If you don't need those workspaces, you can delete this file instead.
    mv /var/lib/qcom/data/qualcomm_launcher/workspaces2.json /var/lib/qcom/data/qualcomm_launcher/workspaces2.json.bak

    # Uninstall Qlauncher
    qsc-cli tool uninstall qualcomm_launcher
    ```
  </Accordion>

  <Accordion title="mkdir .netrc: permission denied">
    **Full error excerpt:**

    ```text
    Updating files: 100% (64/64), done.
    2024-02-29T07:58:00: Sync Command Completed
    2024-02-29T07:58:01: Finished setup.
    [Info]: Setting Docker Credential
    2024-02-29T07:58:03: Authorization successful
    2024-02-29T07:58:03: Sync Command Starting
    2024-02-29T07:58:03: Running Sync Command for SyncOpenSourceCode - DownloadOpenSource
    docker: Error response from daemon: error while creating mount source path '/usr2/ramevelp/.netrc': mkdir /usr2/ramevelp/.netrc: permission denied.
    2024-02-29T07:58:04: Sync Command Failed
    [Error]: Failed SP Download with error: 2024-02-29T07:58:04: Sp Download failed. ExitCode: 126 Signal: 0  with errorcode 4
    [Error]: 2024-02-29T07:58:04: Sp Download failed. ExitCode: 126 Signal: 0
    ```

    **Solution:** This is caused by the way your IT team has configured your home directory. Work with your IT administrator to resolve the home directory permissions.
  </Accordion>

  <Accordion title="fatal: couldn't find remote ref refs/heads/qcom-linuxSTXscarthgap">
    **Full error:**

    ```text
    fatal: couldn't find remote ref refs/heads/qcom-linuxSTXscarthgap
    ```

    If you see stray characters while copying commands from a PDF, remove or replace them with the correct symbols and rerun the command.

    **Example:** Replace:

    ```bash
    repo init -u https://github.com/quic-yocto/qcom-manifest -b qcom-linuxSTXscarthgap -m qcom-x.x.xxx-QLI.x.x-Ver.x.x.xml
    ```

    With:

    ```bash
    repo init -u https://github.com/quic-yocto/qcom-manifest -b qcom-linux-scarthgap -m qcom-x.x.xxx-QLI.x.x-Ver.x.x.xml
    ```
  </Accordion>

  <Accordion title="pull access denied for ECR repository">
    **Full error excerpt:**

    ```text
    Unable to find image '032693710300.dkr.ecr.us-west-2.amazonaws.com/stormchaser/ql-tool:20.04.20231220102843864.9' locally
    docker: Error response from daemon: pull access denied for 032693710300.dkr.ecr.us-west-2.amazonaws.com/stormchaser/ql-tool, repository doesn't exist or may require 'docker login': denied: Your authorization token has expired. Reauthenticate and try again.
    ```

    **Solution:** Remove the stale Docker credentials file and rerun the `qsc-cli` command:

    ```bash
    rm -rf ~/.docker/config.json
    ```
  </Accordion>
</AccordionGroup>

## Build

<AccordionGroup>
  <Accordion title="bitbake-server might have died or been forcibly stopped (OOM killed)">
    **Full error:**

    ```text
    ERROR: Executing event: bitbake-server might have died or been forcibly stopped, ie. OOM killed
    ```

    This error is triggered when builds run on systems with insufficient memory.

    **Solution:** Check current memory usage and increase swap space to more than 32 GB if the build is failing due to OOM:

    ```bash
    free -h
    ```

    See [Increase swap space](/how-to#increase-swap-space) for instructions on enlarging the swap area.
  </Accordion>

  <Accordion title="No valid terminal found, unable to open devshell">
    **Full error:**

    ```text
    ERROR: linux-kernel-qcom-6.6-r0 do_menuconfig: No valid terminal found, unable to open devshell.
    Tried the following commands:
          tmux split-window -c "{cwd}" "do_terminal"
          tmux new-window -c "{cwd}" -n "linux-kernel-qcom Configuration" "do_terminal"
          xfce4-terminal -T "linux-kernel-qcom Configuration" -e "do_terminal"
          terminology -T="linux-kernel-qcom Configuration" -e do_terminal
    ```

    This error is triggered when running `bitbake linux-kernel-qcom -c menuconfig`.

    **Solution:** Install `screen` and `tmux`:

    ```bash
    sudo apt install screen
    sudo apt install tmux
    ```
  </Accordion>

  <Accordion title="No reply from server in 30s">
    **Full error:**

    ```text
    NOTE: No reply from server in 30s
    ```

    If this error appears on a rerun of `qsc-cli chip-software compile` or `bitbake`, delete the lock files from your partially built workspace and retry.

    For example, if you are building with `qsc-cli`, these files are found under `<absolute_workspace_path>/DEV/LE.QCLINUX.2.0/build`:

    - `bitbake.lock`
    - `bitbake.sock`
    - `hashserve.lock`
  </Accordion>

  <Accordion title="BitBake Fetcher Error: Unable to fetch URL from any source">
    **Full error:**

    ```text
    do_fetch: BitBake Fetcher Error: FetchError('Unable to fetch URL from any source')
    ```

    These are intermittent fetch failures. First, check whether there is a network or host issue on your end, or whether the upstream server is causing the failure.

    **Solution:** Increase `postBuffer` and `maxRequestBuffer` in your `.gitconfig` file. If you are using `qsc-cli`, these settings are already configured by the tool:

    ```bash
    git config --global http.postBuffer 1048576000
    git config --global http.maxRequestBuffer 1048576000
    ```

    If the error persists, retry the compile. For large git projects, you can manually clone the failing project as a workaround:

    ```bash
    cd <workspace_path>/downloads/git2/
    git clone --bare --mirror https://<url>/<project-name>.git <workspace_path>/downloads/git2/<local-name>.git
    touch <workspace_path>/downloads/git2/<local-name>.git.done
    ```

    **Example** — when `do_fetch` fails for `qualcomm_linux-spf-2-0-le-qclinux-1-0-r1_api-linux_history_prebuilts.git`:

    ```bash
    git clone --bare --mirror https://qpm-git.qualcomm.com/home2/git/revision-history/qualcomm_linux-spf-2-0-le-qclinux-1-0-r1_api-linux_history_prebuilts.git <workspace_path>/downloads/git2/qpm-git.qualcomm.com.home2.git.revision-history.qualcomm_linux-spf-2-0-le-qclinux-1-0-r1_api-linux_history_prebuilts.git
    touch <workspace_path>/downloads/git2/qpm-git.qualcomm.com.home2.git.revision-history.qualcomm_linux-spf-2-0-le-qclinux-1-0-r1_api-linux_history_prebuilts.git.done
    ```

    After creating the `.done` file, continue with `bitbake <image recipe>`. After your initial build succeeds, set up a dedicated [download directory](https://docs.yoctoproject.org/4.0.16/singleindex.html#term-DL_DIR) to avoid this issue in future builds.
  </Accordion>

  <Accordion title="/bin/sh: Argument list too long">
    **Full error:**

    ```text
    make[4]: /bin/sh: Argument list too long
    ```

    This error occurs when the workspace path exceeds 90 characters.

    **Solution:** Reduce the length of your workspace path and retry the build.
  </Accordion>

  <Accordion title="fatal error: dt-bindings/iio/qcom,spmi-adc7-pmk8350.h: No such file or directory">
    **Full error:**

    ```text
    kernel-source/arch/arm64/boot/dts/qcom/qcm6490-idp.dts:8:10: fatal error: dt-bindings/iio/qcom,spmi-adc7-pmk8350.h: No such file or directory
    ```

    The `qcom,spmi-adc7-pmk8350.h` file is part of the kernel source at `<kernel-src>/include/dt-bindings/iio/qcom,spmi-adc7-pmk8350.h`.

    **Solution:**

    1. Check your workspace for this file and verify that the environment is initialized to find it. During `dtbs` compilation, the kernel build system runs a GCC preprocessor that replaces macros in `.dts` files — the `include` paths must resolve correctly.
    2. Check whether `core.symlinks` is set to `false` in your git configuration. If it is, set it to `true`:

       ```bash
       git config --global core.symlinks true
       ```
  </Accordion>

  <Accordion title="history_prebuilts.git failed with exit code 128, no output">
    **Full error:**

    ```text
    qpm-git.qualcomm.com.home2.git.revision-history.qualcomm_linux-spf-2-0-le-qclinux-1-0-r1_api-linux_history_prebuilts.git –progress failed with exit code 128, no output
    ```

    Exit code 128 is a masking error that can indicate a network issue on your end, or a genuine problem accessing Qualcomm or upstream mirrors.

    **Workaround:** See the [BitBake Fetcher Error](#bitbake-fetcher-error-unable-to-fetch-url-from-any-source) solution above.

    **Verbose logging for further triage:** By default, verbose logging is not enabled for Yocto git fetch. Enabling it for all recipes can significantly increase build time — enable it only for the specific recipe you are debugging.

    To enable verbose logging for all git projects, add the following to your `local.conf`:

    ```text
    BB_GIT_VERBOSE_FETCH = "1"
    ```

    To enable verbose logging for a single recipe — for example, the `diag` recipe:

    1. Edit `layers/meta-qcom-hwe/recipes-bsp/diag/daig_15.0.bb` and add:

       ```text
       BB_GIT_VERBOSE_FETCH = "1"
       ```

    2. Clean previously downloaded artifacts:

       ```bash
       bitbake -fc cleanall diag
       ```

    3. Fetch the source again:

       ```bash
       bitbake -fc fetch diag
       ```

    4. Retrieve the verbose log from the recipe's working directory:

       ```text
       build-qcom-wayland/tmp-glibc/work/qcm6490-qcom-linux/diag/15.0-r0/temp/log.do_fetch
       ```

    5. Share the `log.do_fetch` file with the Qualcomm support team.
  </Accordion>

  <Accordion title="Sp Download failed: No space left on device (ExitCode 128)">
    **Full error excerpt:**

    ```text
    warning: redirecting to https://git-na-ssl.chipcode.qti.qualcomm.com/...
    remote: Counting objects: 129803, done.
    remote: Compressing objects: 100% (114948/114948), done.
    fatal: write error: No space left on device5 GiB | 1.63 MiB/s
    fatal: fetch-pack: invalid index-pack output
    2024-03-02T14:32:18: Sync Command Failed
    [Error]: Failed SP Download with error: 2024-03-02T14:32:18: Sp Download failed. ExitCode: 128 Signal: 0 with errorcode 4
    [Error]: 2024-03-02T14:32:18: Sp Download failed. ExitCode: 128 Signal: 0
    ```

    **Solution:** The error `fatal: write error: No space left on device` indicates your disk is full. Free up disk space and retrigger the build.
  </Accordion>

  <Accordion title="locale.Error: unsupported locale setting">
    **Full error:**

    ```text
    File "/usr/lib/python3.10/locale.py", line 620, in setlocale return _setlocale(category, locale)locale.Error: unsupported locale setting
    ```

    **Solution:** Run the following commands and recompile:

    ```bash
    sudo locale-gen en_US.UTF-8
    sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
    export LC_ALL=en_US.UTF-8
    export LANG=en_US.UTF-8
    ```
  </Accordion>

  <Accordion title="pyinotify.WatchManagerError: No space left on device (ENOSPC)">
    **Full error:**

    ```text
    pyinotify.WatchManagerError: No space left on device (ENOSPC)
    ```

    **Solution:** Increase the maximum number of inotify user watches:

    ```bash
    sudo su
    echo 1048576 > /proc/sys/fs/inotify/max_user_watches
    ```
  </Accordion>
</AccordionGroup>
